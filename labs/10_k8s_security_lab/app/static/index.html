🛡️ Kubernetes Security & Defense Hardening (CKS Guide)

1. RBAC Least Privilege

ServiceAccount에 cluster-admin 또는 광범위한 리소스(Secrets, Pods) 권한을 부여하지 마십시오.

  • RoleBinding은 네임스페이스 격리 원칙 준수
  • Secrets에 대한 get, list 권한 엄격 통제
  • 정기적인 RBAC 감사: kubectl-who-can 활용

2. Pod Security Standards (PSS)

위험한 볼륨 마운트 및 호스트 권한 탈취를 네임스페이스 레벨에서 원천 차단하십시오.

  • pod-security.kubernetes.io/enforce: restricted 적용
  • hostPath 볼륨 사용 전면 금지
  • privileged: true 및 CAP_SYS_ADMIN 차단

3. ServiceAccount Token Protection

토큰 자동 마운트를 비활성화하고 Bound Service Account Token을 적용하십시오.

  • automountServiceAccountToken: false 명시
  • 단기 수명 토큰(Projected Token) 기본 강제
  • 네트워크 정책(NetworkPolicy)으로 API 서버 접근 제한

4. Node & Runtime Security

Falco 및 eBPF 기반 실시간 런타임 위협 탐지를 배포하십시오.

  • Falco 규칙으로 컨테이너 내 nsenter 실행 실시간 차단
  • Kubelet --anonymous-auth=false 적용
  • 읽기 전용 루트 파일시스템 (readOnlyRootFilesystem: true) 강제
