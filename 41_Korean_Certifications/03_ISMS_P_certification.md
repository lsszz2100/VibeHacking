# ISMS-P 정보보호 및 개인정보보호 관리체계 인증

## 0. 초보자를 위한 개념 이해

### ISMS-P란?

**ISMS-P**는 한국에서 조직의 정보보호 및 개인정보보호 수준을 공식적으로 인증하는 제도입니다.

**인증이 왜 필요한가:**
```
법적 의무:
  정보통신망법, 개인정보보호법에 따른 의무
  → 미이행 시 과태료, 형사처벌 가능
  
비즈니스 이점:
  - 공공기관 입찰 시 가점
  - 고객 신뢰 향상
  - 보안 사고 시 면책 근거
  - 국제 비즈니스에서 보안 역량 증명
```

**ISMS-P 역사:**
```
2002년: ISMS(정보보호관리체계) 인증 도입
2013년: PIMS(개인정보보호관리체계) 인증 도입
2018년: ISMS + PIMS 통합 → ISMS-P
  - 중복 인증 부담 해소
  - 102개 통제 항목으로 통합
```

### ISMS-P vs ISO 27001 비교

| 항목 | ISMS-P | ISO 27001 |
|------|--------|-----------|
| 발급 기관 | KISA (한국) | 국제 인증기관 |
| 적용 범위 | 국내 법규 반영 | 국제 표준 |
| 개인정보 | 포함 | 선택적 |
| 의무 여부 | 일부 기업 의무 | 자발적 |
| 심사 주기 | 1년마다 (3년 재인증) | 연간 감시 심사 |

### 인증 취득 프로세스

```
1단계: 준비 (약 6개월~1년)
  - 정보보호 정책/지침 수립
  - 위험 평가 실시
  - 102개 통제 항목 구현
  
2단계: 심사 신청
  - KISA에 심사 신청
  - 예비 심사 (서류 검토)
  
3단계: 현장 심사 (약 3~5일)
  - 심사원이 직접 방문
  - 서류 + 인터뷰 + 기술 점검
  
4단계: 인증위원회 심의
  - 심사 결과 검토
  - 인증 여부 결정
  
5단계: 인증서 발급
  - 유효기간 3년
  - 매년 1회 사후 심사
```

## ISMS-P 개요

ISMS-P(Information Security Management System - Privacy)는 기존 ISMS(정보보호관리체계)와 PIMS(개인정보보호관리체계)를 통합하여 2018년 11월부터 시행된 통합 인증 제도이다. 과학기술정보통신부와 개인정보보호위원회가 공동 고시로 운영하며, 한국인터넷진흥원(KISA)이 인증 업무를 수행한다.

### 인증 의무 대상 (ISMS 기준)

| 대상 | 기준 |
|------|------|
| 정보통신서비스 제공자 | 매출액 100억 원 이상 또는 일평균 이용자 수 100만 명 이상 |
| 집적정보통신시설 사업자 | IDC 운영 사업자 |
| 병원 | 100병상 이상 |
| 학교 | 재학생 1만 명 이상 대학 |
| 공공기관 | 정보통신망 서비스 제공 공공기관 |

## 증적 문서 작성 방법

### 정책(Policy) 작성 원칙

정책은 조직의 정보보호에 대한 최고경영자의 의지와 방향을 담은 최상위 문서이다.

**필수 포함 요소:**
1. 목적 및 적용 범위
2. 정보보호 기본 원칙 및 방침
3. 조직 구성원의 역할과 책임
4. 위반 시 처벌 기준
5. 효력 발생일 및 최고경영자 서명

**예시 정책 구조:**
```
제1조 (목적)
제2조 (적용범위)
제3조 (정의)
제4조 (정보보호 원칙)
제5조 (조직 및 역할)
제6조 (위반 시 조치)
부칙 (시행일)
```

### 지침(Guideline) 작성 원칙

지침은 정책을 실행하기 위한 세부 규정이다.

**예시: 패스워드 관리 지침**
- 최소 8자 이상 (영문 대소문자, 숫자, 특수문자 조합)
- 분기별 1회 이상 변경
- 이전 3회 사용 비밀번호 재사용 금지
- 5회 오류 시 계정 잠금

### 절차서(Procedure) 작성 원칙

절차서는 지침을 실제 수행하는 단계별 방법을 기술한 문서이다.

**예시: 계정 신청 절차서**
1. 신청자: 계정 신청서 작성 (신청 사유, 필요 권한 명시)
2. 부서장: 신청서 검토 및 승인
3. 정보보안팀: 보안 정책 준수 여부 검토
4. IT팀: 계정 생성 및 권한 부여
5. 정보보안팀: 계정 생성 확인 및 기록
6. 신청자: 보안 서약서 서명 후 계정 수령

## 결함 유형 및 대응 사례

### 주요 결함 유형 분류

#### 경미한 결함 (Minor Finding)
- 문서 버전 관리 미흡 (날짜, 버전 번호 누락)
- 교육 이수율 미달 (전 직원의 일부 미이수)
- 로그 보존 기간 일부 미준수

#### 중요 결함 (Major Finding)
- 위험 평가 미수행 또는 문서 미비
- 관리자 계정 공유 사용
- 개인정보 처리방침 미공개
- 외부 위탁업체 계약서 보안 조항 누락

#### 치명적 결함 (Critical Finding)
- 개인정보 대량 유출 발생
- 방화벽 미운영
- 보안 관리 체계 전반적 부재

### 결함 대응 사례

**사례 1: 접근 권한 미검토**
- 결함 내용: 퇴직자의 계정이 삭제되지 않고 유지됨
- 즉각 조치: 해당 계정 즉시 비활성화 및 패스워드 변경
- 근본 원인: 퇴직 처리 프로세스에 IT 계정 회수 절차 누락
- 개선 조치: 퇴직 처리 체크리스트에 계정 회수 항목 추가, HR 시스템과 연동

**사례 2: 개인정보 암호화 미적용**
- 결함 내용: DB에 주민등록번호가 평문으로 저장
- 즉각 조치: 접근 권한 최소화 및 로그 모니터링 강화
- 개선 계획: 3개월 이내 전체 암호화 적용 (이행 계획서 제출)
- 사후 확인: 암호화 적용 후 재심사

**사례 3: 위험 평가 미수행**
- 결함 내용: 최근 2년간 위험 평가 수행 기록 없음
- 즉각 조치: 위험 평가 즉시 수행 및 결과 문서화
- 개선 조치: 매년 위험 평가 일정 수립, 담당자 지정

def load_checklist() -> dict:

        try:

                return json.load(f)
        except (json.JSONDecodeError, OSError):
            return {}
    return {}


def save_checklist(data: dict) -> None:
    try:
        with open(CHECKLIST_FILE, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)
    except OSError as e:
        print(f"저장 실패: {e}", file=sys.stderr)

        print("-" * 70)

        for item in items:

            current = checklist.get(item_key, {}).get("status", "?")
            print(f"[{item['id']}] {item['name']} (위험도: {item['risk']})")
            print(f"  설명: {item['desc']}")
            print(f"  현재 상태: {current}")

            status = input("  이행 상태 (Y/N/P/S/Enter=유지): ").strip().upper()

            if status in ("Y", "N", "P", "S"):
                checklist[item_key] = {
                    "name": item["name"],
                    "status": status,
                    "domain": domain_name,
                    "risk": item["risk"],
                    "updated": datetime.datetime.now().isoformat(),
                }
            print()

    save_checklist(checklist)
    print("점검 결과가 저장되었습니다.")


def generate_report() -> None:
    checklist = load_checklist()

    if not checklist:
        print("점검 데이터가 없습니다. 먼저 자가점검을 수행하세요.")
        return

    stats: dict[str, dict] = {}
    for item_id, info in checklist.items():
        domain = info.get("domain", "기타")
        status = info.get("status", "?")
        risk = info.get("risk", "중")

        if domain not in stats:
            stats[domain] = {"Y": 0, "N": 0, "P": 0, "S": 0, "total": 0}
        stats[domain][status] = stats[domain].get(status, 0) + 1
        stats[domain]["total"] += 1

    total_y = sum(v.get("Y", 0) for v in stats.values())
    total_n = sum(v.get("N", 0) for v in stats.values())
    total_p = sum(v.get("P", 0) for v in stats.values())
    total_all = sum(v.get("total", 0) for v in stats.values())

    print(f"\n{'='*70}")
    print(" ISMS-P 자가점검 결함 요약 리포트")
    print(f" 생성 일시: {datetime.datetime.now().strftime('%Y-%m-%d %H:%M')}")
    print(f"{'='*70}\n")

    print("[ 영역별 이행 현황 ]")
    print(f"{'영역':<20} {'이행':>5} {'미이행':>7} {'부분':>5} {'합계':>5} {'이행률':>7}")
    print("-" * 55)
    for domain, counts in stats.items():
        y = counts.get("Y", 0)
        n = counts.get("N", 0)
        p = counts.get("P", 0)
        total = counts.get("total", 0)
        rate = (y / total * 100) if total > 0 else 0
        print(f"{domain:<20} {y:>5} {n:>7} {p:>5} {total:>5} {rate:>6.1f}%")

    print("-" * 55)
    overall_rate = (total_y / total_all * 100) if total_all > 0 else 0
    print(f"{'전체 합계':<20} {total_y:>5} {total_n:>7} {total_p:>5} {total_all:>5} {overall_rate:>6.1f}%")

    print(f"\n[ 미이행·부분이행 항목 (결함 후보) ]")
    print("-" * 70)
    defects = [
        (item_id, info)
        for item_id, info in checklist.items()
        if info.get("status") in ("N", "P")
    ]

    risk_order = {"상": 0, "중": 1, "하": 2}
    defects.sort(key=lambda x: risk_order.get(x[1].get("risk", "중"), 1))

    if not defects:
        print("결함 없음. 모든 항목이 이행 완료 상태입니다.")
    else:
        for item_id, info in defects:
            status_label = "미이행" if info.get("status") == "N" else "부분이행"
            print(f"[{item_id}] {info.get('name', '')} | 위험도: {info.get('risk', '')} | 상태: {status_label}")

    print(f"\n총 결함 수: {len(defects)}개 (미이행: {total_n}, 부분이행: {total_p})")

## ISMS-P Overview

ISMS-P (Information Security Management System - Privacy) is an integrated certification system that has been in operation since November 2018, combining the existing ISMS (Information Security Management System) and PIMS (Privacy Information Management System). It is jointly issued by the Ministry of Science and ICT and the Personal Information Protection Commission, with the Korea Internet and Security Agency (KISA) conducting certification activities.

| Colocation facilities operators | IDC operators |
| Hospitals | 100+ beds |

| Public institutions | Public institutions providing information and communications network services |

## Types of Findings and Response Cases

### Finding Type Classification

#### Minor Finding
- Insufficient document version management (missing dates, version numbers)
- Below training completion rate (some employees not completed)
- Partial non-compliance with log retention periods

#### Major Finding
- Risk assessment not conducted or documentation insufficient
- Admin account shared usage
- Personal information processing policy not published
- Missing security clauses in external vendor contracts

#### Critical Finding
- Massive personal information breach
- Firewall not in operation
- Overall absence of security management framework

### Finding Response Cases

**Case 1: Access Permission Review Not Conducted**
- Finding: Accounts of resigned employees not deleted
- Immediate action: Immediately deactivate accounts and change passwords
- Root cause: Account revocation procedure missing from resignation process
- Corrective action: Add account revocation item to resignation checklist, integrate with HR system

**Case 2: Personal Information Encryption Not Applied**
- Finding: National ID numbers stored in plaintext in DB
- Immediate action: Minimize access permissions and strengthen log monitoring
- Improvement plan: Apply full encryption within 3 months (submit implementation plan)

**Case 3: Risk Assessment Not Conducted**
- Finding: No risk assessment records for the past 2 years
- Immediate action: Immediately conduct risk assessment and document results
- Corrective action: Establish annual risk assessment schedule, designate responsible person
